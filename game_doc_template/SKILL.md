# 游戏功能文档结构模板

## 概述

本 skill 提供游戏功能设计文档的**标准章节结构和模板示例**，指导 AI 助手按照规范的文档结构组织输出内容。

### 使用场景

- 被 `game_doc_generator` 主流程引用，组织生成文档的章节结构
- **独立调用**：查阅模板结构、对照检查已有文档的章节完整性

### 独立调用触发词

- "查看文档模板"
- "检查文档结构"
- "对照模板"
- "文档应该包含哪些章节"

---

## 双模式章节选用指南

根据文档类型选择对应的章节：

| 章节 | 框架设计文档 | 开发文档 | 说明 |
| --- | --- | --- | --- |
| 文档信息 | ✅ | ✅ | 版本、日期等基础信息 |
| 一、设计目的 | ✅ | ✅ | 功能定位和期望体验 |
| 二、功能概述 | ✅ | ✅ | 背景、简介、结构、入口与退出 |
| 三、规则说明 | ✅ | ✅ | 核心规则，框架文档侧重设计逻辑 |
| 四、客户端和服务器逻辑 | ❌ | ✅ | 仅开发文档需要 |
| 五、界面流程 | ⚠️ 可选简述 | ✅ | 框架文档可简要描述 |
| 六、策划需求 | ✅（6.1/6.2） | ✅（6.1-6.4） | 框架文档不含完整配置表 |

### 写作风格差异

- **框架设计文档**：通俗易懂，侧重设计意图和玩法描述。可以包含"为什么这样设计"的解释。
- **开发文档**：严谨精确，规则/需求章节禁止主观描述。侧重"怎么做"和所有边界条件。

## 文档结构模板

### 文档结构概览

**最小必要章节**（简单功能）：
- 一、功能概述
- 二、规则说明
- 三、数值需求

**完整章节**（复杂功能）：
- 一、设计目的
- 二、功能概述
- 三、规则说明（多个子章节）
- 四、客户端和服务器逻辑（仅开发文档）
- 五、界面流程（可选）
- 六、策划需求（数值、系统、配置表、数据统计）

**关键原则**：确保开发人员能清晰理解功能运作方式。不必死板套用标准模板，可根据功能特点灵活调整。

---

### 标题 + 文档信息

**目的**：提供文档的基本信息和版本管理。

**书写位置**：文档最开头，紧跟在标题之后。

**内容示例**：

```markdown
# 功能名称 功能设计文档

## 文档信息

- **文档版本**：v1.0
- **创建日期**：2026-01-29
- **最后更新**：2026-01-29
- **需求来源**：《XXX需求文档》
- **功能类型**：核心系统/活动玩法/辅助功能
- **目标用户**：客户端和服务器开发人员
```

### 一、设计目的

**目的**：说明为什么要做这个功能，期望达到什么效果。

#### 1.1 功能定位
- 描述功能在游戏中的定位和作用
- 说明功能解决的核心问题或满足的玩家需求
- 示例：
  > 本功能为游戏核心资源获取系统之一，提供稳定的资源产出途径，增强玩家养成体验。

#### 1.2 期望体验
- 描述玩家使用该功能时的预期体验
- 说明功能带来的价值和乐趣
- 示例：
  > 玩家通过简单操作即可获得资源奖励，体验成长的满足感；通过策略选择优化收益，体验决策的乐趣。

---

### 二、功能概述

**目的**：全面介绍功能的基本信息和整体框架。

#### 2.1 背景概述
- 功能的背景故事或世界观设定（如适用）
- 功能在游戏整体设计中的位置
- 示例：
  > 神秘的神石散落在王国各处，蕴含强大的魔法能量，玩家可以搜集神石获得属性加成。

#### 2.2 功能简介
- **核心玩法**：用1-3段话描述功能的核心玩法流程
- **主要特点**：列出功能的3-5个关键特性
- **玩家操作**：简述玩家的主要交互行为
- 示例：
  > 玩家可以在城堡中建造和升级各类建筑。每个建筑都有特定的功能和产出。建筑升级需要消耗资源和时间，玩家可以使用道具加速建造过程。

#### 2.3 结构划分
- 使用**列表**或**思维导图**方式展示功能的结构组成
- 包含功能模块、子系统、主要流程等
- 示例（列表形式）：

  活动中心
  ├── 活动专区
  │   ├── 日常活动
  │   ├── 限时活动
  │   └── 节日活动
  ├── 特惠福利
  │   ├── 首充奖励
  │   └── 累充奖励
  └── 活动公告

#### 2.4 功能入口与退出

**目的**：明确玩家如何进入和离开该功能，确保入口路径和退出逻辑清晰。

**必须说明以下内容**：

| 项目 | 说明要求 |
|------|----------|
| 入口方式 | 玩家从哪里进入此功能？（具体的界面、按钮、图标位置） |
| 入口条件 | 是否有等级要求、任务前置、VIP限制等？ |
| 触发方式 | 主动点击进入、被动弹窗提示、系统推送通知？ |
| 退出方式 | 如何退出功能？点击返回、完成后自动退出、超时退出？ |
| 退出后去向 | 退出后返回到哪个界面？ |

**示例**：

| 项目 | 示例说明 |
|------|----------|
| 入口方式 | 玩家从主界面左上角点击功能图标进入 |
| 入口条件 | 玩家等级达到5级后解锁 |
| 触发方式 | 每日首次登录时弹窗提示，玩家也可主动点击进入 |
| 退出方式 | 点击界面右上角关闭按钮或点击空白区域退出 |
| 退出后去向 | 回到主界面 |

### 三、规则说明

**目的**：详细描述功能的运行规则和逻辑，这是文档的核心部分。

⚠️ **重要原则：禁止使用代码和伪代码**

在描述规则时，**严禁使用任何形式的代码或伪代码**。必须使用纯文本、表格、列表来描述规则。详细的规则编写规范请参考 `game_rule_writing` skill。

⚠️ **术语标注要求**：所有核心功能、游戏元素、操作术语必须使用【】符号标注，保持与项目已有术语一致。

**注意**：⚠️ **以上提示仅供AI参考，不要将这些提示文字写入输出的文档中**

#### 3.1 功能状态机（可选）
- 使用**表格**描述功能的各种状态及转换条件
- 表格格式示例：

| 状态 | 说明 | 进入条件 | 退出条件 |
|------|------|----------|----------|
| 未开启 | 功能尚未解锁 | 游戏初始状态 | 满足开启条件 |
| 进行中 | 功能正在运行 | 活动开始时间到达 | 活动结束或手动退出 |
| 已结束 | 功能已完成 | 完成所有任务 | 重置或刷新 |

#### 3.2 开启条件
- 列出功能解锁的所有条件
- 使用**表格**或**列表**清晰呈现
- 表格格式示例：

| 条件类型 | 具体要求 | 说明 |
|----------|----------|------|
| 玩家等级 | 主堡等级≥5 | 玩家需先升级主堡 |
| 前置功能 | 完成新手引导 | 确保玩家理解基础玩法 |
| 时间限制 | 服务器开服后第3天 | 避免新手期功能过载 |

#### 3.3 参与条件
- 描述玩家进入功能或参与玩法的条件
- 与开启条件的区别：开启条件是功能解锁，参与条件是每次使用的门槛
- 示例：
  > 每日可参与3次，消耗10点体力。VIP等级≥3的玩家可额外获得2次机会。

#### 3.4 循环方式/运行规则
- 描述功能的循环机制（日常/周常/不循环等）
- 适合用**表格**说明不同循环类型
- 表格示例：

| 循环方式 | 循环规则 | 案例 |
|----------|----------|------|
| 日循环 | 每日0点刷新 | 每日任务 |
| 周循环 | 每周一0点刷新 | 周常活动 |
| 固定时间循环 | 每周三、周日开启 | 限时副本 |
| 不循环 | 一次性功能 | 新手奖励 |

#### 3.5 结束规则
- 描述功能结束的条件和方式
- 说明结束后的处理逻辑（奖励发放、数据清除等）
- 表格示例：

| 结束条件 | 结束规则 | 后续处理 |
|----------|----------|----------|
| 时间到期 | 活动结束时间到达 | 自动结算奖励并发送邮件 |
| 任务完成 | 所有任务目标达成 | 弹出完成提示，领取奖励 |
| 手动退出 | 玩家主动关闭 | 保存当前进度 |

#### 3.6 特殊处理/特殊规则
- 列出所有特殊情况及其处理方式
- 包括异常场景、边界情况、容错机制等
- 表格示例：

| 特殊情况 | 处理方式 |
|----------|----------|
| 玩家在功能进行中等级下降 | 保持当前状态，直到本次结束后重新检查 |
| 网络断线 | 保存断线前进度，重连后可继续 |
| 资源不足以完成操作 | 弹出提示，引导玩家前往获取资源 |
| 背包已满无法领取奖励 | 奖励发送至邮件，保留7天 |

**开发注意事项** ⚠️ **重要**（仅开发文档）：

在每个相关规则章节末尾，添加该规则的实现注意事项。这些注意事项应该：
- 直接跟在相关规则后面，不要单独成章
- 使用"**开发注意事项**："作为标题
- 列举该规则实现时的关键点，如数据同步、性能优化、作弊防护、体验优化等

示例：
```
**开发注意事项**：
- **数据同步**：玩家的【基础属性】必须实时同步到服务器，避免数据丢失
- **性能优化**：每日计算可以在玩家登录时异步执行，避免阻塞主流程
```

#### 3.7 红点提示规则（可选）
- 说明红点显示的触发条件和消失条件
- 表格示例：

| 提示位置 | 出现条件 | 消失条件 |
|----------|----------|----------|
| 功能入口按钮 | 有未领取奖励 | 领取所有奖励 |
| 任务列表 | 有可完成任务 | 查看任务详情 |
| 活动专区 | 有新活动开启 | 进入活动界面 |

#### 3.8 [其他功能特定规则]
- 根据具体功能添加其他必要的规则说明
- 常见的额外规则类型：
  - **建筑功能**：升级规则、加速规则、建造队列规则
  - **战斗功能**：伤害计算、技能释放、胜负判定
  - **养成功能**：经验计算、突破规则、属性加成
  - **社交功能**：好友上限、互动规则、协作机制

**填写建议**：
- 善用**表格**来组织结构化信息
- 对于复杂规则，可以使用**公式**或**流程图描述**（文字描述流程）

### 四、客户端和服务器逻辑（仅开发文档）

⚠️ **此章节仅在开发文档模式下使用，框架设计文档请跳过。**

**目的**：清晰描述客户端和服务器各自的职责，以及它们之间的数据交互，让前后端开发人员能明确各自需要实现的内容。

⚠️ **重要原则**：同样禁止使用代码/伪代码，必须使用自然语言、表格、列表来描述逻辑。

#### 4.1 客户端逻辑

描述客户端在该功能中负责的职责范围，应覆盖以下方面：

**显示和交互**：
- 渲染功能界面的所有UI元素
- 展示玩家当前状态（等级、资源、进度等）
- 处理玩家的点击、拖拽等输入操作
- 播放动画效果和音效反馈

**本地验证**：
- 检查玩家操作是否合法（例如：是否有足够资源）
- 验证输入参数的有效性
- 进行基础的逻辑判断（例如：是否满足操作条件）
- 防止无效请求发送到服务器

**数据缓存**：
- 缓存从服务器获取的配置数据
- 保存玩家的操作记录（用于断线重连）
- 临时存储未提交的操作状态

**开发注意事项**：
- **前端校验**：所有本地验证仅用于改善用户体验，不可替代服务器验证
- **缓存更新**：配置数据缓存需要在版本更新时刷新

#### 4.2 服务器逻辑

描述服务器在该功能中负责的职责范围，应覆盖以下方面：

**数据持久化**：
- 存储玩家在该功能中的所有进度和状态
- 记录玩家的历史操作和成就
- 保存功能相关的全局数据（如排行榜）

**业务逻辑验证**：
- 验证客户端请求的合法性
- 检查操作是否符合游戏规则
- 防止作弊和异常操作
- 验证资源消耗和奖励计算的正确性

**核心计算**：
- 计算玩家操作的结果（战斗结算、任务完成度等）
- 处理随机事件和概率判定
- 计算奖励数量和类型
- 更新玩家的各项数值和状态

**数据同步与系统联动**：
- 将更新后的数据发送给客户端
- 处理多端登录的数据一致性
- 触发其他系统的相关逻辑（如成就系统、任务系统等）
- 发送系统通知和奖励邮件

**开发注意事项**：
- **安全性**：所有涉及资源和奖励的操作必须在服务器端验证和执行
- **幂等性**：关键操作接口应设计为幂等，防止重复提交导致数据异常

#### 4.3 客户端-服务器交互协议

列出功能涉及的所有关键通信协议。每个协议应包含以下要素：

- **触发时机**：什么时候发起通信
- **客户端请求**：发送什么数据（字段列表）
- **服务器响应**：返回什么数据（字段列表）
- **异常处理**：请求失败时的处理方式

**常见协议类型参考**：

| 协议类型 | 触发时机 | 说明 |
|---------|---------|------|
| 进入功能 | 玩家打开功能界面 | 请求功能初始数据和玩家状态 |
| 执行核心操作 | 玩家执行主要玩法操作 | 验证操作、计算结果、返回奖励 |
| 领取奖励 | 玩家点击领取 | 验证条件、发放奖励、更新状态 |
| 数据同步 | 定期或关键节点 | 保持客户端与服务器数据一致 |
| 退出功能 | 玩家离开功能界面 | 保存状态、上传未提交的数据 |

**协议描述示例**：

**协议1：进入功能**
- **触发时机**：玩家点击功能入口按钮
- **客户端请求**：发送玩家ID、请求时间戳
- **服务器响应**：返回玩家当前状态、可用资源、配置数据
- **异常处理**：超时则提示网络异常，请求失败则使用本地缓存数据

**协议2：执行核心操作**
- **触发时机**：玩家执行主要玩法操作
- **客户端请求**：发送操作类型、操作参数
- **服务器响应**：返回操作是否成功、消耗的资源、获得的奖励、更新后的状态
- **异常处理**：操作失败则回滚客户端状态，提示失败原因

**通用交互原则**：
- 客户端发起所有主动操作请求，服务器负责验证和计算
- 所有涉及奖励、数值变化的操作必须由服务器处理和确认
- 客户端只展示服务器返回的结果
- 关键操作需要防重放、防篡改验证

### 五、界面流程（可选）

**目的**：提供功能的界面原型和交互说明，便于UI/UE设计和客户端开发。

**使用场景**：
- 当策划完成原型图绘制后，可将原型图和UE说明补充到此章节
- 此章节为**可选内容**，在文档初期生成时可以暂时省略
- 框架设计文档中可简要描述界面流程，不需要详细原型

#### 5.1 界面原型

**内容要求**：
- 提供功能相关界面的原型图（可以是手绘、设计稿或成品截图）
- 使用markdown图片语法嵌入原型图：`![界面名称](图片路径)`
- 每个界面原型图需要简要说明其用途和显示时机

**示例结构**：

```markdown
#### 主界面原型
![主界面](./prototypes/main_ui.png)
- **显示时机**：玩家点击功能入口后显示
- **主要元素**：功能标题、资源显示、任务列表、操作按钮

#### 奖励弹窗原型
![奖励弹窗](./prototypes/reward_popup.png)
- **显示时机**：完成任务领取奖励时弹出
- **主要元素**：奖励内容、确认按钮、分享按钮
```

#### 5.2 UE交互说明

**内容要求**：
- 描述用户与界面的交互方式和反馈
- 说明界面跳转逻辑和动画效果
- 明确各种状态下的界面表现

**推荐格式**：

| 交互操作 | 触发条件 | 界面反馈 | 跳转/变化 |
|---------|---------|---------|----------|
| 点击功能入口按钮 | 满足开启条件 | 按钮高亮，播放点击音效 | 打开主界面 |
| 点击任务"提交"按钮 | 完成任务目标 | 按钮高亮，播放成功音效 | 弹出奖励确认窗口 |
| 点击"升级"按钮 | 资源充足 | 播放升级动画，更新数值显示 | 留在当前界面，刷新显示 |
| 点击"关闭"按钮 | 无 | 播放关闭音效 | 关闭当前界面 |

#### 5.3 动画效果说明（可选）

**内容要求**：
- 描述关键操作的动画效果

| 动画类型 | 触发时机 | 动画描述 | 时长 | 是否可跳过 |

### 六、策划需求

**目的**：明确功能实现所需的数值配置和系统支持。

#### 6.1 数值需求
- 列出所有需要配置的数值参数
- **必须明确区分硬编码参数和可配置参数** ⚠️

**硬编码参数示例**（固定值，不需要在配置表中存储）：

**可配置参数示例**（需要在配置表中设计字段）：

**参数标注规范**：
- 在规则说明中提到参数时，必须注明是否可配置
