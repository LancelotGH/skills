# 标准 Markdown 格式化规范

在设计、创建、修改或整理项目内的所有 Markdown 文档时，**必须**严格遵循以下排版规则，以确保文档在各类渲染器（及后续导出转换引擎中）表现一致且无格式错乱。

## 1. 标题层级规范
- **禁止使用序号前缀**：在各类文本级标题中严禁出现诸如“一、”、“1.”、“1.1”、“(1)”等人工序号前缀。
- **使用纯粹的 Markdown 语法**：只依赖 Markdown 原生的 `#`, `##`, `###` 符号来表示标题和逻辑层级。由于最终将导出到能自动生成序号的格式，硬编码的数字会导致编号重叠。

## 2. 列表标号规范
- **无序列表统一**：所有的无序列表项目前缀必须统一使用连字符 `- `（即减号加一个空格）。
- **禁止混用**：不得使用 `* `（星号）或 `+ `（加号）作为无序列表前缀，以保持整个项目代码风格的绝对一致性。

## 3. 表格格式规范
- **表前必须留空行（核心防错）**：在标准的 Markdown 语法中，任何一个表格的开始之前**必须且只能有一行纯空行**。严禁表格代码片段紧贴着上一段文字直接开始，否则会导致各类平台渲染器和 Word 导出工具将其误认为连续文本，导致全盘展示乱码。
- **标准分隔符补全**：表头的下方必须使用标准的 Markdown 分隔符，如 `| --- |` 或 `| :--- |`。要避免表头分隔符周围缺少空格。
- **首尾管道符**：每一行表格内容的最开始和最末尾必须包含单独的管道标志 `|`。
- **避免多余标识**：表格单元格内避免使用过多影响兼容性的 HTML 标签（如 `<br>`），如果必须要表达复杂的多行层级关系，应当将其拆分放到表格外部以列表展开，或者将表格拆解为常规文本段落。

## 4. 纯文本树状结构处理
- **禁用特殊字符画**：严禁在正文、引用区块甚至是代码块内使用 `├─`、`└─`、`│` 等特殊制表符来绘制所谓的“文字伪树状图”或思维导图。
- **降级为原生列表**：所有企图以文本形式展现层级包含关系的内容，应毫不例外地替换为**带缩进的标准 Markdown 嵌套无序列表**（使用 `- ` 递进结构）。

## 5. 目录 (TOC) 处理
- **移除页面内文目录**：不要在文档开头或任意段落包含类似 `[TOC]` 等语法命令，也不要人工手写一份带描点的“本页目录”段落。现代工具集会在边栏生成和阅读或导出工具自身的生成逻辑生成结构树，强行置入内文目录会显得非常累赘冗杂。

## 总结：执行强制要求
在你收到修改或校对单个/多个文档的工作请求时，请像“代码 Linter（风格检查器）”一样对所操作的文档段落扫视这 5 个关键格式问题，并进行修复，**在未满足上述所有前提时，不要向用户交付任何包含格式异味的文档成果**。
